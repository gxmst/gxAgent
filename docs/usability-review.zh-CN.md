# UI 与模型连接审查

审查日期：2026-11-11。范围：桌面窗口配置、主界面、全局设置、会话设置、供应商预设、API Profile 和模型选择。本文记录初次审查和后续修复；下文九项为改造前发现的问题，当前均已实施修复。

## 结论

主要问题是连接数据和操作流程没有围绕“一个供应商连接”组织起来，视觉上也缺少清晰的操作层级。当前前端使用 React 19、Radix 和自定义 CSS，并非整体使用 Windows 原生 UI；Windows 标题栏和边框由 Tauri 窗口配置决定。可沿用现有技术栈改造。

## 已复现的功能缺陷

### 1. P1：切换供应商沿用旧密钥，并保留旧连接的启用标记

- 位置：`src/hooks/useConfigActions.ts:70`，特别是 `api_key: preset.needs_api_key ? prev.api_key : ""`。
- 复现：配置旧供应商和密钥，启用旧 Profile，再点击一个需要密钥的新供应商预设。
- 结果：Base URL 和模型已经改变，旧密钥仍然存在，旧 Profile 仍标记“使用中”；修改还会自动保存。如果随后发送请求，旧密钥可能被发送到新地址。
- 另一个后果：全局配置与已保存 Profile 分离，继承全局的会话和显式选择旧 Profile 的会话可能使用不同连接，启用标记无法说明这种差异。
- 修复要求：新建连接采用独立草稿；密钥只属于对应连接。切换连接要整体切换地址、协议、密钥、模型和连接 ID。修改现有连接时明确保存到该连接。

### 2. P1：全局模型菜单包含其他连接的模型，但选择时不切换连接

- 位置：`src/components/settings/SettingsModal.tsx:298`。
- 复现：全局使用 Ollama，另有 Anthropic Profile；在全局模型下拉框选择这个 Profile 的 Claude 模型。
- 结果：配置模型变成 `claude-private-model`，供应商和协议仍为 Ollama，地址仍为 `http://localhost:11434`。模型名会被交给错误的服务。
- 修复要求：模型菜单只展示当前连接的模型；跨连接选择必须明确切换连接。显示“供应商 / 模型”，不能只按模型 ID 识别。

### 3. P1：自定义模型不在目录时，显示值与实际配置不一致

- 位置：`src/components/settings/SettingsModal.tsx:314`。
- 复现：当前模型为 `my-private-model`，模型列表获取成功，但不包含该 ID。
- 结果：保存的模型仍为 `my-private-model`，原生下拉框却显示 `deepseek-r1`。当前模型的兜底选项仅在列表为空时出现。
- 同时，供应商模型字段是不可输入的 `select`；网关不支持模型目录或使用自定义模型 ID 时，用户无法正常手填。Codex 的独立模型输入框不解决该问题。
- 修复要求：使用可搜索、可手填的模型选择器；始终展示当前模型。目录不可用不应阻止手工配置。

### 4. P2：保存失败后仍关闭设置

- 位置：`src/hooks/useConfigActions.ts:198`、`src/components/settings/SettingsModal.tsx:773`。
- 复现：让 `save_config` 返回错误，点击“保存设置”。
- 结果：保存函数内部捕获错误，调用方仍继续关闭窗口；用户失去查看错误和立即重试的入口。
- 修复要求：保存返回明确成功状态；失败时保留表单和窗口，并在相关位置展示错误和重试。保存期间防止重复提交。

## 流程和界面问题

### 5. P2：添加网关必须先修改正在使用的全局配置

位置：`src/components/settings/SettingsModal.tsx:189`、`src/hooks/useConfigActions.ts:83`、`src/App.tsx:566`。

当前顺序是“预设 / 地址 / 密钥 / 模型 → 输入配置项名字 → 保存快照”。没有独立的“添加供应商”入口，名字和保存按钮还位于连接字段上方。字段修改约 650 毫秒后自动落盘，因此用户尝试添加新网关时已在修改全局默认连接，关闭窗口也不意味着取消。

建议以连接列表为入口，提供“添加供应商”，点击后选择官方供应商、本地 Ollama 或自定义网关。表单只编辑草稿，保存后加入连接列表，是否设为默认作为明确选项。

### 6. P2：Profile 缺少完整管理操作，同名保存会直接覆盖

位置：`src-tauri/src/lib.rs:838`、`src/components/settings/SettingsModal.tsx:190`、`src/utils/requestConfig.ts:46`。

Profile 名称直接作为存储键，同名保存使用 `insert` 覆盖，界面没有冲突提示；列表只有启用和删除，没有明确编辑、重命名和复制。删除没有确认，会话仍可保留已删除的 Profile ID，解析时退回全局连接。

建议连接使用稳定 ID，名称仅用于展示。提供编辑、复制、删除；重名给出明确处理方式。删除前展示受影响会话，并提供替换连接或取消的选择。一次连接维护模型列表，避免为同一网关的每个模型重复存一份密钥。

### 7. P2：连接诊断反馈不足

位置：`src/hooks/useConfigActions.ts:39`、`src/components/settings/SettingsModal.tsx:318`。

供应商连接只有小型刷新图标用于获取模型，成功或错误进入日志，缺少表单内的连接状态、地址校验和错误修正提示。Codex 连接检查却放在本页最前面，即使默认引擎为 gxAgent 仍展示其可执行文件和模型字段。

建议把“获取模型”和“检查连接”做成有文字的操作，在当前连接内展示状态；区分地址错误、认证失败、超时、目录接口不支持。目录成功不应宣称所有模型都能正常对话。Codex 放到独立的编码引擎区，只展开所选引擎需要的字段。

### 8. P2：重复入口和作用范围不清楚

位置：`src/components/workspace/WorkbenchHeader.tsx`、`src/components/sidebar/Sidebar.tsx:492`、`src/components/sidebar/Sidebar.tsx:522`、`src/components/chat/ChatHeader.tsx`、`src/components/chat/Composer.tsx`。

侧栏顶部和底部都有全局设置按钮；工具页也有顶部快捷入口和底部状态入口。会话设置同时出现在会话标题栏、输入栏权限按钮和回复选项中；模型同时出现在全局设置、会话设置及输入栏，混用“配置项 / Profile / API / 模型”等名称。

建议保留一个全局设置入口；输入栏负责当前会话的模型和常用回复选项；会话菜单负责其余会话设置。权限快捷按钮可保留，但应直接打开权限项。全局默认与本会话覆盖要持续可见，重复入口仅在有明确快捷价值时保留。

### 9. P2：窗口外框、控件和文字层级缺乏统一

位置：`src-tauri/tauri.conf.json:20`、`src/styles/workbench.css:19`、`src/styles/workbench.css:264`、`src/styles/tokens.css`。

主窗口只配置 `titleBarStyle: "Overlay"`，没有关闭系统装饰；这一配置不能替代 Windows 无边框窗口方案。界面又包含自己的品牌区和任务标题栏。大量操作采用 30px 的纯图标按钮，设置表单和辅助信息广泛使用 11–13px 文字，灰色层级接近。原生 `select` 弹出菜单与页面自定义控件也不统一。

建议采用应用自绘标题栏，统一品牌、窗口拖拽和最小化 / 最大化 / 关闭操作；保留系统缩放、贴靠和键盘行为。常用操作提高辨识度，低频动作收进菜单。统一字体、间距、控件高度、圆角和焦点样式；先完成浅色、深色主题，再核对其他主题。

维护上，`overlays.css` 与最后加载的 `workbench.css` 重复定义设置布局、圆角和表单样式。后续应整理到明确负责该组件的样式文件，避免继续叠加覆盖规则。

## 建议实施顺序与验收

1. **供应商管理及请求一致性**：独立添加 / 编辑表单、稳定连接 ID、密钥隔离、模型可手填、连接诊断；修复以上四个已复现缺陷。旧 Profile 自动迁移并保持会话关联。
2. **窗口与导航**：自绘标题栏、整理全局 / 会话入口、明确连接和模型的作用范围、按所选编码引擎展开设置。
3. **视觉与可访问性**：统一控件和主题、提高中文可读性、补全表单标签及键盘交互，再检查缩放和较窄窗口。

供应商流程验收示例：

> 添加供应商 → 选择“自定义网关” → 填写名称、地址、密钥 → 获取或手填模型 → 查看检查结果 → 保存 → 在输入栏选择“连接 / 模型”。

需要同时验证：取消添加不改变当前连接；不支持模型目录仍能保存；同一模型 ID 在不同连接下不串线；保存失败保留草稿；删除被使用的连接有明确处理；旧配置迁移后密钥和会话关联仍正确。

窗口验收包括拖动、双击最大化、还原、最小化、关闭、缩放、贴靠、键盘操作和高 DPI；不能只通过修改 `decorations` 判断完成。

## 本轮修复结果

| 问题 | 已实施的修复 |
| --- | --- |
| 1. 密钥与供应商串线 | 独立连接草稿，切换预设和复制均清空密钥；保存、启用时整体应用连接字段。 |

## MCP 与工具链复查

| 环节 | 发现及处理 |
| --- | --- |
| 配置 | 参数按 JSON 数组或逐行解析，避免逗号拆分；环境变量拒绝格式错误、重复名称和 NUL；后端拒绝重名覆盖。 |
| Windows 启动 | 标准 npm/npx 通过 node.exe + CLI 脚本启动，保留包含空格、逗号和 shell 字符的字面参数。 |
| 协议 | 服务端 ping / 请求不会吞掉客户端同 ID 响应；不支持的服务端请求明确返回 -32601。 |
| 取消与退出 | 取消 / 超时释放 pending 请求并发送取消通知；服务停止后快速失败；结束服务时清理子进程树和读取任务。 |
| 工具目录 | 检查分页、重复工具、目录大小和 JSON Schema；跨服务同名工具通过稳定别名隔离路由。 |
| 执行与审批 | 拒绝非法参数对象、已禁用工具和未提供工具；Chat 也遵守工具开关；审批仍遵守原有策略。 |
| 错误与回传 | MCP isError / RPC / 运行错误传给模型并标记 UI 失败；保留原生调用和结果关联，避免错误显示为成功。 |
| 调试 | 配置变化后丢弃旧目录、旧调用结果及错误，审批绑定确认时的服务、工具和参数。 |

Chat 保留只读内置工具的产品范围；Work 的 gxAgent 引擎使用本地 MCP；Codex 按既有 app-server 接入传递 MCP 配置，使用自己的工具和权限机制。本次未新增远程 HTTP MCP、采样或根目录能力。

## 截图反馈后的布局修复

用户反馈的整页会话列表来自 1180px 断点：系统或浏览器缩放减少 CSS 视口宽度后，打开侧栏会隐藏整个聊天区。现已调整为：801px 以上普通窗口保留侧栏与聊天区并排；窄屏或中等窗口同时打开审查面板时自动收起侧栏，再打开时进入有遮罩的限宽抽屉，通过 Esc、遮罩或选择会话关闭，主工作区保留。侧栏内部统一跟随容器宽度，避免旧响应式规则与保存的宽度冲突。

新增 1147px / 5⁄3 DPR 的中文回归（接近反馈截图），覆盖 801 / 900 / 1147 / 1179px 并排区域不重叠、会话切换保留侧栏、抽屉关闭以及窄屏操作。空间恢复后自动恢复原侧栏可见状态；主动收起的侧栏保持收起，保存的宽度也不被缩放覆盖。真实 Windows 调试程序也已确认浅色和深色稳定布局、完整聊天区和双击最大化；全部使用 GXAGENT_DATA_DIR 隔离测试数据。
