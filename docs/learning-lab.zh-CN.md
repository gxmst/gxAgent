# gxAgent 学习与调试指南

这套工具用于观察一次请求从技能选择、资料检索、上下文组装到工具调用的过程。完整功能需要通过 `npm run tauri dev` 启动桌面应用；单独的 Vite 页面不具备本地文件和数据库接口。

## 建议的学习顺序

1. 在“设置 > 工具与 MCP”配置一个本地 stdio 服务，点击“读取工具”，查看工具的输入 Schema。手动输入参数，分别试一次成功调用和错误参数，观察错误来自参数校验还是工具执行。手动调用需要确认，会启动独立服务进程，结束后关闭。
2. 在“设置 > 知识库”导入几份你熟悉的 Markdown 文档。先不启用自动检索，使用“检索实验”检查问题命中了哪些原文。分别改变分块长度、重叠长度、Top K 和匹配方式，每次只改一个变量。
3. 建立一组固定问题，给每题选择预期文档，并加入几道资料中没有答案的问题。运行评测，比较 Hit@K、MRR 和无答案检索结果。每份报告都保存索引版本、参数和当时的命中片段，可导出 JSON。
4. 打开“回答前检索”，在对话中提问。点击回答中的数字引用查看当时采用的原文，再点“查看上下文”核对这些片段是否进入请求。修改文档后需要重新索引；已有回答保留原来的证据。
5. 添加一个简单 Skill，启用后重复同一道题，对比上下文中的技能指令和回答变化。会话设置可以独立开关知识库，并覆盖全局技能选择。

## Skill 示例

在项目的 `.agents/skills/docs-reader/SKILL.md` 中定义：

```markdown
---
name: docs-reader
description: Answer questions from project documents with citations.
---
Use the retrieved passages to answer document questions.
Cite each supported claim with its supplied [KB:chunkId].
When the evidence is insufficient, say which information is missing.
```

名称使用小写字母、数字与连字符，描述和正文不能为空。在技能页面刷新后勾选它。项目目录内的技能只在该项目被发现，全局技能可放在 `~/.agents/skills` 或设置中添加的目录中；也支持 `<project>/.gxagent/skills`。

脚本与参考资料可放在技能目录内，页面支持查看文本。启用技能会把正文及来源路径加入系统指令，不会自动执行脚本。模型执行脚本时仍经过当前引擎的工具权限和审批流程。

如果技能依赖一个 MCP 服务，可在技能目录的 `agents/openai.yaml` 中声明，`value` 对应应用中的服务名称：

```yaml
dependencies:
  tools:
    - type: mcp
      value: docs
```

缺少服务时会显示缺失项并阻止依赖不完整的技能运行。这里只检查服务是否已配置，实际连接状态仍需通过 MCP 调试确认。原生引擎的 MCP 工具用于 Work 模式。Codex CLI 自己发现的技能和服务仍受其自身配置控制，gxAgent 的技能开关控制的是应用额外注入的指令。

## 检索与评测

当前实现使用 SQLite FTS5 的 BM25 排序，中文按相邻双字生成检索词。默认分块 800 字符、重叠 120 字符、Top K 为 5，可在页面调整。匹配方式可选任意关键词或全部关键词。

“当前项目与全局”会检索两种范围，新增资料归当前项目；“全局”只操作全局资料。移除文档只删除索引，不删除原文件。重新索引在事务中替换片段，失败会保留原有索引。

支持文本、Markdown、CSV、JSON、RST、PDF、DOCX、XLSX 和 PPTX。单文件不超过 30 MB，提取文本不超过 8 MB。PDF 依赖 PATH 中的 Poppler `pdftotext`，不包含扫描件 OCR；Office 提取仅支持 Windows。

| 指标 | 含义 |
| :--- | :--- |
| Hit@K | 有预期文档的问题中，前 K 个片段命中该文档的比例 |
| MRR | 预期文档首次命中位置的倒数均值，未命中计 0 |
| 无答案判定 | 标记“无答案”的问题中，检索未返回任何片段的数量 |

这里评估的是检索。即使命中文档，片段也可能不支持答案；关键词无命中也不代表资料没有答案。应结合原文逐题检查。向量 Embedding、混合检索、重排以及模型回答质量评测可以在这套固定问题上继续研究。

索引和检索不需要额外模型接口。启用回答前检索后，命中片段会加入当前问题并发送给所选模型，因此“本地索引”不表示资料永远不会离开设备。

## 上下文记录

原生引擎记录每次模型调用前的规范化消息和工具定义，供应商适配层随后转换为实际请求格式。Codex 引擎仅记录 gxAgent 交给 CLI 的输入和指令，无法显示 CLI 内部读取的全部规则、技能或压缩结果。

每条回答保留最近六次调用快照，重试产生的不同回答分别保留自己的记录和出处。快照对大内容设置约 160,000 字符预算，截断时会标记；图片载荷和常见凭据字段会隐藏。这不是通用秘密扫描器，消息和工具结果仍可能包含敏感内容。导出前应检查内容。

## 保存与恢复

空闲时内容变化会触发短暂防抖保存；持续流式输出时每 5 秒尝试保存一次。失败后保留未保存状态，并在后续保存周期重试。突然终止应用仍可能损失最后一个保存周期内的数据。

自动快照保留上一个有效会话版本，普通写入最多每 5 分钟生成一次；删除和批量替换前强制生成。手动创建快照会先等待最新会话保存成功。快照不会自动清理。

可读的会话支持“恢复副本”，原会话保持独立。损坏会话可从已有快照修复，损坏原文件的字节另存到 `recovery` 目录。恢复后不沿用旧 Codex 线程，避免接入快照之后的隐藏历史。正在执行或等待审批的工具会标记为中断，恢复不会自动执行它们；继续前需要核对文件和外部系统状态。

数据保存在系统应用数据目录：

| 平台 | 根目录 |
| :--- | :--- |
| Windows | `%APPDATA%/gxAgent/` |
| macOS | `~/Library/Application Support/gxAgent/` |
| Linux | `~/.local/share/gxAgent/`，或 `$XDG_DATA_HOME/gxAgent/` |

`sessions/` 保存会话，`sessions/backups/` 保存快照，`sessions/recovery/` 保留修复前的损坏文件。`knowledge.sqlite3` 保存文档片段、全文索引、评测问题和报告；运行期间可能同时存在 SQLite 的 WAL / SHM 文件。需要完整迁移时先退出应用，再备份整个数据目录。会话导出 JSON 不包含知识库数据库、Skill 原文件或其资源。
